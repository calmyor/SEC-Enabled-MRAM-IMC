# Public measurement-method reference

This small package makes the paper-level analysis flow inspectable without
publishing test-chip secrets, board credentials, foundry collateral, or the
hardware controller. It uses only the Python standard library.

## What is implemented

- **Per-column affine calibration.** `fit_affine_calibration` fits the MMSE map
  `reference = gain * measured + offset`; `fit_column_calibrations` repeats the
  fit independently for each ADC column.
- **Code-conditioned sampling.** `sample_measurement_protocol` defaults to 30
  randomly selected states for every ideal output code and 10 measurements per
  selected state. That is 300 measurements per code, per ADC column. Selection
  and request ordering are reproducible from a seed.
- **Code-conditioned SNDR.** `code_conditioned_sndr` first computes residual MSE
  for each ideal code, then evaluates
  `Var(y_o) / sum(P(c) * MSE_code(c))`. Both signal variance and residual power
  use the same normalized code probabilities. The returned object includes the
  exact powers, normalized probabilities, per-code MSE, and sample counts as
  well as the dB result.
- **Signed dot-product distribution.**
  `signed_dot_product_code_probabilities(N)` returns the paper's binomial
  distribution for the codes `-N, -N+2, ..., N` when each signed product is
  independently positive with probability 0.5.
- **Synthetic SEC illustration.** `learn_synthetic_correction_factors` shows how
  shared multiplicative factors can compensate systematic row attenuation in a
  toy numerical model.

## Important boundary

The synthetic learner is an educational method demo. It is **not** the
proprietary hardware controller, tapeout RTL, PYNQ firmware, fixed-point update
engine, or a bit-accurate reproduction of the fabricated macro. Board-specific
register maps, bitstreams, foundry files, raw lab captures, and identifying test
records are intentionally excluded.

The routines should therefore be used to understand and reproduce analysis
principles, not to claim a turnkey reconstruction of the chip.

## SNDR probability convention

The papers assume `P_Y ~ Bi(N, 0.5)` for an `N`-dimensional signed binary dot
product. To reproduce that convention, pass the helper's output explicitly:

```python
code_probabilities = signed_dot_product_code_probabilities(N)
result = code_conditioned_sndr(
    ideal_codes,
    calibrated_outputs,
    code_probabilities=code_probabilities,
)
```

If `code_probabilities` is omitted, the function deliberately defaults to the
empirical code frequencies in `ideal_codes`. This default is useful for general
datasets, but an equal-state-count measurement campaign would then give every
code equal weight and would **not** reproduce the paper metric. Explicit values
may be normalized probabilities or arbitrary nonnegative weights. To request
equal-code weighting intentionally, pass `{code: 1.0 for code in codes}`.

## Run the example

From the repository root, install the local package and run the deterministic
demo:

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -e .
python3 examples/protocol_demo.py
```

The output reports the requested sample count, the synthetic learner's MSE, and
calibrated SNDR before and after the illustrative correction for two simulated
ADC columns. These numbers are generated by the toy model and are not measured
silicon results.

## Run the tests

The test suite also has no third-party dependencies:

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

## Minimal API example

```python
from sec_mram_imc import (
    code_conditioned_sndr,
    fit_affine_calibration,
    sample_measurement_protocol,
    signed_dot_product_code_probabilities,
)

calibration = fit_affine_calibration(
    measured=(-1.7, 0.3, 2.3),
    references=(-1.0, 0.0, 1.0),
)

states_by_code = {
    -1: tuple(range(40)),
    +1: tuple(range(40, 80)),
}
requests = sample_measurement_protocol(states_by_code, seed=17)

ideal_codes = (-1.0, -1.0, 1.0, 1.0)
estimates = calibration.apply_many((-1.7, -1.6, 2.2, 2.3))
result = code_conditioned_sndr(
    ideal_codes,
    estimates,
    code_probabilities=signed_dot_product_code_probabilities(1),
)
print(result.db)
```

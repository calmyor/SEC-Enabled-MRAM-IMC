Overview / Tapeout

Mixed-signal implementation discipline

Tapeout is a sequence of evidence gates.

For this macro, “tapeout” connected bit-accurate SEC logic, sensitive current sensing, a dense MRAM array, pad and package constraints, power integrity, and future observability. This page documents the engineering questions and review artifacts without publishing foundry-confidential implementation data.

Process map

Freeze intent, prove interfaces, then close the physical design.

The phases overlap in practice, but each needs an explicit exit condition. A final database is not ready because a date arrived; it is ready when the evidence package is internally consistent and every remaining exception has an owner and disposition.

Cross-domain closure

Four reviews must agree on the same signal path.

A mixed-signal IMC can pass each local review and still fail at the boundary between them. These are the boundary questions that mattered most.

MODEL ↔ CIRCUIT

Is α still representative?

Extracted parasitics, sensor headroom, and input ordering must stay inside the modeled correction range.

CIRCUIT ↔ DIGITAL

Is conversion deterministic?

Auto-zero, evaluation, SAR control, capture, and SEC update phases need unambiguous cycle and reset semantics.

DIE ↔ PACKAGE

Can the pins carry it?

Pad type, bond map, simultaneous switching, references, supplies, and safe unused states must agree.

PACKAGE ↔ BENCH

Can the result be observed?

The board and FPGA must reach every mode, control timing, limit current, and preserve raw ADC data with metadata.

Review ledger

What a defensible signoff record contains.

For every qualified run

  • Immutable design identifier and checksum.
  • Tool, rule-deck, library, extraction, and corner versions.
  • Command/configuration provenance and run timestamp.
  • Summary counts linked to reviewable detail.
  • Owner and disposition for every nonzero category.
  • Cross-probe evidence for representative violations.
  • Relationship to the exact handoff database.

For every waiver

  • Exact rule, cell/hierarchy, and affected geometry.
  • Why the result is intentional rather than ignored.
  • Electrical, reliability, yield, and integration impact.
  • Foundry or IP-owner concurrence when required.
  • Scope narrow enough to prevent masking new errors.
  • Revalidation after fill, ECO, or database regeneration.
Archive caution

The internal archive contains run summaries with nonzero counts and intermediate status. This public site does not reinterpret them as a clean-signoff claim. Final signoff status belongs to the qualified release ledger and foundry review, not to an isolated report copied from a working directory.

Design for observability

The bench begins at tapeout.

Scan chains, bypasses, raw ADC visibility, independent write/read/MVM modes, controllable clocks, deterministic reset, SEC state access, and current-isolation options are architectural features—not accessories added after fabrication.

Minimum bring-up ladder

Power integrity → static interface → scan-chain loopback → deterministic register access → single-cell read/write → raw ADC capture → MVM → calibration → SEC learning → repeated statistical measurement.

Public artifact boundary

Document the process without redistributing the process kit.

The source archive is a working record, not an open ASIC release. This repository publishes new, sanitized process guidance and an availability matrix.

PUBLIC

Engineering method

Phase map, review checklists, interface questions, package/board coordination, artifact taxonomy, and measured paper results.

DERIVED

Sanitized summaries

Redrawn block diagrams, aggregate specifications, safe figures, and descriptions that remove personal, supplier, and foundry details.

RESTRICTED

Implementation collateral

PDK/configuration data, validator material, raw rule reports, waivers, export forms, GDS/OASIS, netlists, commercial IP, and personal paths.

Availability finding: the audited archive does not contain a reproducible open RTL-to-GDS flow, final source database, netlists, or a complete signoff package. This site therefore makes no open-source ASIC implementation claim.
